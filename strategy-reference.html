## 3. Pattern A–B–C–D–E–F

ทุกการเปรียบเทียบ pattern ใช้ **Close** ไม่ใช่ High/Low ของแท่ง

- **A:** บริบทก่อน pattern ไม่มี separate A filter ที่ executable code บังคับ
- **B:** local close peak เมื่อ `Close[B] > Close[B−1]` และวันถัดไป
  `Close[B+1] < Close[B]` หนึ่งค่า B ต่อ candidate ไม่เลื่อน B ภายใน candidate
  การรู้ว่าเป็น B ต้องรอแท่งถัดไป ไม่ใช้ข้อมูลอนาคตตัดสินซื้อในวัน B
- **C:** เริ่มจาก negative-close day หลัง B (`Close[t] < Close[t−1]`)
  และเลื่อนไปเฉพาะ negative-close day ที่ Close ต่ำกว่า C เดิมระหว่างค้นหา D
  เก็บสองค่าในวันเดียวกัน: **C_close** สำหรับ pattern/invalidation และ
  **C_low** สำหรับ ATR trailing stop เมื่อ D finalize แล้ว C ถูกตรึง
- **D:** rally ที่สูงกว่า B และเป็น positive-close day; ขยาย D เมื่อสูงขึ้น
  code ยังติดตาม highest Close จริงตั้งแต่หลัง B เพื่อไม่ให้ rebound ที่ต่ำกว่า
  high เก่าถูกใช้เป็น breakout threshold ใหม่ D finalizes เมื่อเจอแท่งที่ไม่
  ขยาย D ภายหลังมี D แล้ว โดย branch ที่อัปเดต C ยังมีลำดับก่อน finalize
- **E:** ช่วง pullback หลัง D finalize ระหว่างรอ F ไม่จำเป็นต้องมีแท่ง E เดียว
  Close ต่ำกว่า C_close ทำให้ candidate ยกเลิก; เท่ากับ C ไม่ยกเลิก
- **F:** แท่งแรกหลัง finalize ที่ `Close[F] > highest prior Close` ของ candidate
  และ `Close[F] > Close[F−1]` เป็น pivot signal ทันที ไม่รอแท่งถัดไปยืนยัน F
  เท่ากับ D ไม่ใช่ breakout และแท่ง finalize D ไม่ fire F ใน branch เดียวกัน

ติดตามหลาย B candidates พร้อมกันได้ เมื่อหลาย candidate fire วันเดียวกัน
ใช้ signal เดียวและเลือก metadata ของ B ล่าสุด ไม่ซื้อซ้ำตามจำนวน candidates
`reference_window=63` ใน pivot API เป็น vestigial parameter ไม่ใช่ expiry pattern

ตัวอย่าง Close: `100,105,102,99,100,110,105,107,111`
B=105, C_close=99, D=110, F=111 หากแท่ง C มี Low=91 ใช้ 91 คำนวณ trail
ไม่ใช้ 91 เป็น C threshold สำหรับ pattern

## 4. Entry และ earnings correction

เมื่อ F fire ตรวจ reference ล่าสุด: วัน gap หลัง earnings ใช้ **Open** เป็น R
ใช้ทั้ง gap ขึ้นและลง ช่วงซื้อทันทีไม่เกิน `1.10 × R`
หากราคาเหนือ band ให้ WAITING_CORRECTION รอ Low แตะ ceiling แล้วเข้าที่
`min(Open, ceiling)` หรือปล่อยเมื่อ reference อายุครบ 21 trading bars ให้เข้า Close
ถ้าไม่มี reference/gate ก็เข้าตาม pivot ที่ Close ของวันสัญญาณ

ใน waiter code ประเมิน touch/expiry **ก่อน** C_close invalidation:
หากแท่งเดียวกันทั้งแตะ ceiling และปิดต่ำกว่า C อาจเข้าได้ตามลำดับนี้
WAITING ไม่ใช่ holding และไม่นับ concurrent exposure; reconfirmed waiter ถูก merge
ไม่ปล่อยหลาย duplicate buys พร้อมกัน

**ข้อแตกต่างที่ต้องเปิดเผย:** reference +302.92% เปิด
`use_golden_cross_gap_override=True` ใน backtest โดยรวมราคา SMA Golden Cross
เข้ากับ reference lookup (ค่า cross ของวันเดียวกัน overwrite earnings reference)
ไม่ใช่การเปิด SMA entry gate ระบบ live ไม่ใช้ override นี้ ผล offline gap-only
ต้นทุนเดียวกันคือ +299.66%, DD −27.90%, WR 42.62%, avg loss −12.34%
ห้ามเรียก +302.92% ว่า production parity จนกว่าจะทดสอบ/รับรองความต่างนี้

## 5. Initial SL

ATR14 เป็น arithmetic rolling mean ของ True Range 14 แท่ง ไม่ใช่ Wilder RMA
`TR = max(High−Low, abs(High−priorClose), abs(Low−priorClose))`

`distance = clamp(2.5 × ATR14 / entry_price, 0.10, 0.25)`

`initial_SL = entry_price × (1 − distance)`

ATR missing มี fallback flat 10% ใน code ต้องแจ้ง ไม่ใช่ยืนยันว่า ATR พร้อมเสมอ
แต่ละ pyramid slot เริ่ม SL ของตนเอง (`shared_initial_stop=False`)
SL ไม่ใช่ guarantee ขาดทุนสูงสุด: overnight gap/slip/commission ทำให้เสียมากกว่าได้

## 6. Trailing stop (TS)

มี fresh valid pivot ให้ candidate trail จาก **C_low** ของ pattern ใหม่:
`buffer = clamp(2.5 × ATR14 / C_low, 0.10, 0.25)`
`candidate_TS = C_low × (1 − buffer)`
เท่ากับ C_low−2.5×ATR เฉพาะเมื่อ raw buffer อยู่ระหว่าง floor/cap เท่านั้น
ใช้ `max(active_stop, candidate_TS)` ยกเท่านั้น ไม่ลด stop เดิม
ยกกับ slots ที่ถืออยู่ของ symbol เดียวกัน ไม่มี signal-close ratchet อื่นเปิดอยู่
ATR unavailable มี fallback `C_low × 0.995`

SL/TS เป็น protective stop ตัวเดียวที่เดินขึ้น ไม่ใช่สองคำสั่งขายให้ยิงซ้ำ
event log แยกเหตุ initial SL / trailing TS และ slot ownership ได้
กำไรขาดทุนจาก TS อาจยังติดลบ และ SL gap อาจเกินระยะตั้งต้น

## 7. Take profit: POC tiered FULL CLOSE

POC approximation ใช้ expanding history ถึงวันปัจจุบัน 250 price bins
นำ volume ทั้งแท่งลง bin ของ typical price `(High+Low+Close)/3`
ไม่ใช่ true trade-by-trade volume profile ของตลาด

กำหนด tier จาก `entry_price / POC_at_entry`:

| Ratio | Tier | Target gain | Target price |
|---|---:|---:|---:|
| > 2.0 | 1 | +29.655% | entry × 1.29655 |
| > 1.5 และ ≤ 2.0 | 2 | +74.655% | entry × 1.74655 |
| ≤ 1.5 | 3 | +299.655% | entry × 3.99655 |

แตะด้วย **Close** ไม่ใช่ High; ปิดเต็ม slot ที่ Close แล้วปรับ slippage/fee
ทุก tier → CLOSED ไม่มี partial half exit ไม่มี TP1_TAKEN executable state
เมื่อ assign แล้ว tier/target ไม่เลื่อนตาม POC ภายหลัง
Corner case: ถ้า entry ยังไม่มี POC code retry assign ด้วย Close/POC ในวันถัดที่พร้อม
จึงต้องบันทึก tier assignment time ไม่อ้าง fixed-at-entry ในกรณี missing POC

## 8. ลำดับเหตุการณ์ในแท่งเดียว

1. สำหรับ slot ที่ถือมาก่อน ตรวจ Low กับ **stop เดิม** ก่อน
2. ถ้าทะลุ stop ปิดที่ `min(Open, stop)` แล้วปรับ sell slippage และ fee
3. ถ้าไม่โดน stop จึง raise trailing จาก pattern ใหม่
4. ตรวจ Close กับ TP แล้วปิดเต็มถ้าผ่าน
5. ประมวลผล entry/waiter ตาม engine; entry ใหม่ไม่โดน same-bar stop ย้อนหลัง

ไม่ใช้ TS ที่เพิ่งคำนวณจากข้อมูลหลังจบวันขายที่ Low ก่อนหน้าในวันเดียวกัน
ถ้าแท่ง Low โดน old stop และ Close ผ่าน TP ให้ stop มี priority
แบบจำลองอาศัย daily bars ไม่รู้ real intraday tick chronology/actual fills

## 9. Pyramiding, form-after-stop และทุน

Pyramiding เปิดอยู่ new distinct F อาจเปิด slot เพิ่ม ไม่มี max_positions hard cap
หลัง protective stop ต้องใช้ B ที่เกิด **หลัง** stop watermark เพื่อ reenter
ไม่ใช้ old pattern กลับเข้าซ้ำ รวมถึง candidates ที่เกิดก่อน stop

35 sleeves ใช้ทุนเริ่ม symbol ละ 10,000 บาท หรือ USD285.714 ที่ FX35
entry desired notional =95% ของ starting sleeve (9,500 บาท ไม่ใช่95%ของNAVใหม่)
ซื้อ integer shares ได้ไม่เกิน affordable cash หลัง fee; เติมไม้ภายในเงินของ sleeve
ไม่ยืมทุน symbol อื่น ไม่มี leverage และไม่ได้เติมเงินใหม่ต่อ slot
จึงมีบาง symbol/บาง signal ที่ซื้อไม่ได้ทั้งที่ pivot fire (เช่นราคาเกินทุนต่อหุ้น)
9500 เป็น notional ก่อน rounding/fee ไม่ใช่ actual fill รับประกัน
